# Практическая работа № 2

Серверное приложение на Node.js и Express.js. API управляет списком задач. Данные хранятся в памяти процесса, поэтому после перезапуска список очищается.

## Запуск в Windows

В PowerShell из папки проекта при установленном Node.js 20 или новее:

```powershell
npm.cmd ci
npm.cmd start
```

Сервер доступен по адресу `http://127.0.0.1:3002`. Проверка запуска — `GET /health`. Порт 3002 позволяет запускать эту работу одновременно с практической № 3.

## Структура приложения

В `server.js` создаётся Express-приложение. Запрос сначала проходит через middleware журналирования и разбора JSON, затем передаётся маршрутизатору `express.Router()`, подключённому по префиксу `/api/tasks`. Middleware параметра `:id` ищет задачу, а `validateTask` проверяет тело POST и PUT. После маршрутов подключены обработчик неизвестных адресов и middleware ошибок.

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | /health | Проверка запуска, 200 |
| GET | /api/tasks | Список задач, 200 |
| POST | /api/tasks | Создание, 201 |
| GET | /api/tasks/:id | Чтение задачи, 200 |
| PUT | /api/tasks/:id | Замена полей задачи, 200 |
| DELETE | /api/tasks/:id | Удаление, 204 |

Поля запроса — обязательное название `title` и необязательный логический флаг `done` со значением `false` по умолчанию. API возвращает 400 при ошибке валидации или некорректном JSON и 404 для отсутствующей задачи или маршрута.

## Проверка в Postman

1. Запусти сервер и оставь окно PowerShell открытым.
2. В Postman выбери **Import** и открой `Express Tasks.postman_collection.json`.
3. Запусти всю коллекцию через **Run collection** в исходном порядке. Запрос создания автоматически сохраняет ID для следующих запросов.
4. На защите покажи результаты запуска коллекции, обработчики маршрутов и middleware в `server.js`, а также лог запросов в окне сервера.
